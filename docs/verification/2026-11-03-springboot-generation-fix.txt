5. Root cause and fix (summary)
===============================================================================
Root cause: OracleCapture compiled the target's production sources with
"-classpath" set to the tool's own runtime only, and started the capture JVM
with "-cp <classes>;<tool runtime>". The analysed repository's Maven
dependencies were never resolved, so any source referencing a third-party
package (org.springframework.*, org.springframework.orm.hibernate5, ...) failed
with "package ... does not exist" and the generator produced 0 tests. Plain
JDK-only projects were unaffected, which hid the defect.

Fix: MavenClasspathResolver resolves the target revision's compile classpath by
running `mvn dependency:build-classpath` inside an isolated checkout of that
revision (uses the project's own POM, BOM/dependency management and transitive
resolution; nothing hardcoded, nothing downloaded through any external
service). The resolved classpath is threaded through TestGenerator /
IncrementalGenerator into OracleCapture, which adds it to both the javac
-classpath and the capture JVM's -cp. Failure to resolve raises an exception
whose message is Maven's own diagnostic.
